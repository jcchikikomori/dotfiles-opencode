## What This Is

A [GNU Stow](https://www.gnu.org/software/stow/)-managed dotfiles package for OpenCode, the terminal AI coding assistant. It configures:

- **[oh-my-opencode-slim](https://github.com/alvinunreal/oh-my-opencode-slim)** — an agent orchestration plugin with 7 specialized agents (Orchestrator, Explorer, Oracle, Librarian, Designer, Fixer, Observer) that automatically route work to the right specialist
- **29 workflow subagents** for ticket-to-PR pipelines (PRD creation, technical design, code review, security review, etc.)
- **60+ skills** covering languages (Ruby, Python, Java, Node.js, PHP, Android), frameworks (Rails, React, Vue, Angular, Spring Boot, FastAPI, Grails), databases, infrastructure (Docker, Kubernetes, Git), and workflow tooling
- **10 MCP servers** for library docs (context7), GitHub integration, browser automation (camoufox), web research (web-forager), and more
- **Tmux multiplexer integration** for live subagent visibility
- **Background orchestration** with `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS`

**omo-slim agents** are capability-specialized (research, architecture, code execution) and handle routing automatically. **Workflow agents** handle structured development phases (requirements → design → implementation → review → PR). The Orchestrator can delegate to both layers.

## Setup

### 1. Stow the Configuration

```sh
# From the parent dotfiles repo
cd ~/Projects/dotfiles
stow -t ~ linux/opencode
```

### 2. Install oh-my-opencode-slim

```sh
bunx oh-my-opencode-slim@latest install --no-tui --skills=yes \
  --background-subagents=yes --companion=no --preset=opencode-go
```

The installer handles:
- Adding the plugin to `opencode.jsonc`
- Disabling default `explore`/`general` agents
- Enabling LSP integration
- Generating `oh-my-opencode-slim.json` with agent model mappings
- Installing 8 bundled skills (codemap, deepwork, simplify, etc.)

### 3. Configure Environment

Add to `~/.profile.local`:

```bash
# Required: background orchestration
export OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true
export OPENCODE_ENABLE_EXA=1

# Required: model selection
export OPENCODE_MODEL="opencode/qwen3.5-plus"
export OPENCODE_SMALL_MODEL="opencode-go/kimi-k2.6"

# Optional: MCP tokens
export GITHUB_PERSONAL_ACCESS_TOKEN="<token>"
export STACK_EXCHANGE_API_KEY="<key>"
export FIGMA_API_KEY="<key>"
# ... see MCP Servers below
```

### 4. Authenticate and Launch

```sh
source ~/.profile.local
opencode auth login        # Authenticate with providers
opencode models --refresh  # Refresh model list
opencode                   # Or: omos (in tmux)
```

### 5. Verify

Inside the opencode TUI, run:

```
> ping all agents
```

All omo-slim agents (Orchestrator, Oracle, Explorer, Librarian, Designer, Fixer, Observer) should respond.

## Plugins

| Plugin | Purpose |
|--------|---------|
| `oh-my-opencode-slim` | Agent orchestration with 7 specialized agents, background tasks, and tmux multiplexer |
| `envsitter-guard@latest` | Prevents accidental exposure of secrets in .env files |
| `@franlol/opencode-md-table-formatter@latest` | Auto-formats markdown tables |
| `opencode-mem` | Memory/context persistence across sessions |
| `opencode-redactor@0.1.1` | Redacts sensitive information from outputs |

### Custom Plugin Hooks

Two TypeScript plugins in `.config/opencode/plugins/`:

- **`git-commit-guard.ts`** — Blocks `git commit` commands (GPG signing requires TTY, opencode sessions lack one)
- **`quality.ts`** — Runs `prettier --write` after every file edit, warns if tests fail

| `framelink-figma` | no | `FIGMA_API_KEY` | [Figma → Personal Access Tokens](https://www.figma.com/developers/api#access-tokens) |

## Model Configuration

Models use **environment variables** for multi-environment support:

```bash
# ~/.profile.local
export OPENCODE_MODEL="opencode/qwen3.5-plus"
export OPENCODE_SMALL_MODEL="opencode-go/kimi-k2.6"

# Or for AWS Bedrock:
export OPENCODE_MODEL="amazon-bedrock/anthropic.claude-sonnet-4-5-20250929-v1:0"
export AWS_REGION="ap-southeast-2"
export AWS_PROFILE="your-aws-profile"
```

### Supported Providers

| Provider | Prefix | Example |
|----------|--------|---------|
| OpenCode (built-in) | `opencode/` | `opencode/qwen3.5-plus` |
| OpenCode Go | `opencode-go/` | `opencode-go/kimi-k2.6` |
| Amazon Bedrock | `amazon-bedrock/` | `amazon-bedrock/anthropic.claude-sonnet-4-5-20250929-v1:0` |
| GitHub Copilot | `github-copilot/` | `github-copilot/claude-sonnet-4` |
| Ollama | `ollama/` | `ollama/qwen2.5-coder:32b` |
| OpenRouter | `openrouter/` | `openrouter/anthropic/claude-sonnet-4` |

### omo-slim Agent Models

Each omo-slim agent can use a different model. Configure in `~/.config/opencode/oh-my-opencode-slim.json`:

| Agent | Default (opencode-go preset) | Role |
|-------|------------------------------|------|
| Orchestrator | `opencode-go/minimax-m3` (thinking) | Plans and delegates work |
| Oracle | `opencode-go/qwen3.7-max` (max) | Architecture, debugging, code review |
| Explorer | `opencode-go/deepseek-v4-flash` (high) | Codebase reconnaissance |
| Librarian | `opencode-go/deepseek-v4-flash` (high) | Documentation and library research |
| Designer | `opencode-go/kimi-k2.7-code` | UI/UX implementation |
| Fixer | `opencode-go/deepseek-v4-flash` (high) | Fast code changes |
| Observer | `opencode-go/mimo-v2.5` | Image/visual file analysis |

Switch the entire team's models at runtime with `/preset` in the TUI.

## Environment Loading

All environment variables (tokens, model config, feature flags) go in `~/.profile.local`. This file is automatically sourced by `~/.zshrc` on shell startup.

```sh
# ~/.profile.local
export OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true
export OPENCODE_ENABLE_EXA=1
export OPENCODE_MODEL="opencode/qwen3.5-plus"
export OPENCODE_SMALL_MODEL="opencode-go/kimi-k2.6"
export GITHUB_PERSONAL_ACCESS_TOKEN="<token>"
```

For project-specific overrides, create `.opencode/.env` in your project root.

## Per-Project Configuration

Override the global config by placing `opencode.jsonc` in your project:

```text
your-project/
├── opencode.jsonc          # option A: project root
└── .opencode/
    └── opencode.jsonc      # option B: hidden directory
```

OpenCode merges configs in this order (last wins):

1. `~/.config/opencode/opencode.jsonc` — global
2. `<project-root>/opencode.jsonc` or `<project-root>/.opencode/opencode.jsonc` — project-level

### Minimal Project Config Example

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "AGENTS.md"
  ],
  "mcp": {
    "sonarqube-mcp": {
      "enabled": true
    }
  }
}
```

## Tmux Multiplexer

The omo-slim plugin auto-detects tmux and opens panes for subagent sessions.

### Setup

The multiplexer config is already set in `~/.config/opencode/oh-my-opencode-slim.json`:

```json
"multiplexer": {
  "type": "auto",
  "layout": "main-vertical",
  "main_pane_size": 60
}
```

### Usage

An `omos()` helper is defined in `~/.profile.local`. It auto-selects a free port and sets `OPENCODE_PORT`:

```sh
# Inside a tmux session:
omos

# With explicit port:
omos --port 4096
```

Then trigger delegated work — subagent panes appear automatically.

## Security

- `~/.profile.local` is the designated place for tokens (not committed to git)
- **Never commit tokens** to git
- Use separate tokens per machine if possible (easier to revoke)
- `envsitter-guard` blocks accidental secret exposure in .env files
- `opencode-redactor` strips sensitive fields from outputs
- `git-commit-guard` prevents commits from opencode sessions (GPG signing requires TTY)
- Bash permissions deny `git commit`, `git push`, and `git reset --hard`
